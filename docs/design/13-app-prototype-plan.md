# 13 · План сборки прототипа приложения (итеративный)

> Решение **D11** (гл.04, 2026-06-04): уточнение расходов — дело настройки, когда
> есть с чем работать. Сначала собираем **работающий прототип приложения**,
> дальше докручиваем онлайн. Слайсы гл.11 остаются логикой валидации норм;
> порядок сборки продукта — эта глава.

## 0. Принципы

1. **Каждая итерация заканчивается артефактом, который открывается на телефоне.**
   Не «модуль готов», а «можно потыкать».
2. **Деплой с первой итерации.** Статик на VPS Димы; `git push → пересборка`.
   «Докрутка онлайн» начинается на P0, а не после релиза.
3. **Честная неопределённость вместо точной лжи.** Seed-нормы не калиброваны —
   UI показывает диапазон + «ориентир» (D7, гл.08 §4). Это снимает конфликт
   «прототип раньше калибровки»: приложение не врёт, оно честно оценивает.
4. **Ядро остаётся чистым.** `crates/compute-core` без зависимостей; WASM-граница —
   отдельная обёртка `crates/compute-wasm` (wasm-bindgen + serde + tsify).
5. **Эталонная квартира (flatplan №1001_527) — первый проект приложения**:
   преднаполненное демо + golden-данные для регрессий UI.

## 2. Архитектурные решения прототипа

- **`crates/compute-wasm`** — единственное место с wasm-bindgen/serde/tsify;
  TS-типы генерятся из Rust (D3/D4), compute-core не трогаем.
- **Персист: IndexedDB напрямую** (idb-обёртка), document-level, single-device.
  Полный sync-движок (outbox, server-assigned revision, tombstones — гл.09 §4)
  НЕ строим, но id-дисциплину держим: client-mint UUIDv7, `org_id` в типах —
  миграция на бэкенд-синк потом без перелопачивания данных.
- **Без auth и без бэкенда** до тех пор, пока единственный пользователь — Дима/Давид
  с одним устройством. Бэкенд-синк = отдельная итерация после P5 (или раньше,
  если появится второе устройство — триггеры гл.09 §5).
- **Деплой**: static на VPS (caddy/nginx), скрипт `deploy.sh` (build + rsync).
  CI потом; на N=1 пересборка руками/скриптом — ок (гл.09 §6 Q18-22).
- **Каталог**: read-only seed.json бандлится в приложение (141 SKU); ре-курация
  руками перед объектом (D10).

## 3. Что сознательно НЕ в прототипе

Без изменений против deferred-таблиц гл.09 §5 / гл.11 §11.6: solver раскладки,
multi-device sync, авто-калибровка, B2B (роли/биллинг), Bluetooth-дальномер,
непрямоугольные комнаты, ReorderPing. Электрика — счётчики точек по шаблонам
(UI-уровень), без материалов в листе.

## 4. Петля «докрутки онлайн»

С P4 каждый реальный объект пишет тройку estimate → actual → reconciliation
прямо в приложении. Калибровка остаётся ручной (гл.11 §11.4: правило трёх
одного знака → сдвиг NormSet новой версией), но теперь её сырьё собирается
само — это и есть «уточнение расходов как настройка», когда есть с чем работать.
Метрика успеха D5 не меняется: доверие = Давид закупается по листу.

## 5. Риски порядка (честно, один раз)

- Seed-нормы до первых сверок могут промахиваться (особенно стяжка/клей —
  Risk #1). Митигация — D7-диапазоны в UI и ранний P4. Это осознанный трейд-офф
  D11, не сюрприз.
- WASM-тулчейн (P1) — первая встреча с wasm-pack/tsify; если затянет,
  fallback: посчитать в TS-прототипе временно, ядро подключить следующей
  итерацией (анти-yak-shaving, гл.11 §11.7).
